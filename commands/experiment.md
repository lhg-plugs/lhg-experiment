# /lhg-experiment:experiment —— 实验设计一条龙

用户输入在 `$ARGUMENTS` 中：研究问题一句话（如"首页改版能不能提升转化率"）。缺省则先问用户要研究问题。

## 流程（全程按 skill 指导执行）

### 1. 澄清假设（加载 exp-design）
把用户的研究问题转成可证伪假设，格式：**「干预 X 使指标 Y 变化 ≥Z%」**。
- 追问三件事：干预是什么（改了什么）、指标是什么（怎么量）、Z 是多少（小到多少就不值得做）。
- Z 定不下来 → 用"最小业务价值法"帮他算：开发成本 ÷ 单用户价值 = 盈亏平衡的提升幅度。

### 2. 选设计（加载 exp-design 第 3 节决策树）
按决策树走：
- 能随机分流 + 有对照 → 随机对照（A/B）
- 不能随机但有前后数据 → 准实验（DID / 断点回归 / 倾向得分匹配）
- 多个因素要一起看交互 → 析因设计
- 用户异质性大 → 区组/分层随机
把选择理由写清楚（一句话：为什么别的方案不行）。

### 3. 功效测算（加载 power-analysis，用脚本算，不许拍脑袋）
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/power_calc.py --test prop2s --p1 <基准> --p2 <期望> --format text
# 均值型指标用 --test t2s --d <Cohen's d>
```
- 效应量来源三选一（历史数据 / 最小业务价值 / 文献），取最保守的。
- 输出 `plan.json`（字段见 fixtures/good/plan.json）：假设、对照、随机化方式、分流比、时长（≥7 天）、α/功效目标、效应量依据、需求样本量、主要指标（1~2 个）、SRM 检查声明。

### 4. 跑确定性审计
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/experiment_audit.py --target <plan.json 所在目录> --format text
```
blocker 清零才能进入执行；warning 要么修要么写理由。

### 5. 结果解读（加载 result-read）
用户拿回数据后，按"显著性→效应量→置信区间→业务意义"四步解读，禁区：
- 不许只报 p 值；不许中途看数提前停；多指标必须校正；事后分组发现标"探索性"。

## 输出
`experiment-plan.md`：假设 / 设计选择 / 功效测算过程 / 执行清单 / 解读预案（含"什么结果算成功、什么结果算失败"的事先声明）。

## 硬规则
- 样本量没经过脚本测算 → 不许进入执行。
- 主要指标超过 2 个 → 打回重定。
- 用户说"先跑起来看看" → 提醒这是 p-hacking 的起点，坚持先定 plan.json。
